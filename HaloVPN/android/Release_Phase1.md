Prerequisites (for the Phase 1 rollout)
- Android Gradle project present at android/
- Keystore material available via one of:
  - android/keystore.properties (CI-generated or locally provided)
  - CI environment variables for store/file, alias, and passwords
- Access to CI secrets: KEYSTORE_PASSWORD, KEY_ALIAS, KEY_PASSWORD, (optional) KEYSTORE_BASE64 or KESTORE_FILE_PATH

Phase 1 Tasks

1) Release signing configuration (Gradle)
- Ensure signingConfigs.release can read from android/keystore.properties when present.
- Provide a safe fallback for local development (warn if signing is not configured).
- Align with current code in android/app/build.gradle:
  - Read storeFile, storePassword, keyAlias, keyPassword from properties
  - Support CI-based provisioning via environment variables if properties are missing
- Verification steps:
  - Verify that a sample android/keystore.properties exists or is generated by CI
  - Run a local release build with signing disabled to verify non-signed behavior, then with signing enabled to verify APK signing

2) CI signing workflow alignment
- CI should:
  - Create android/keystore.properties with:
    - storeFile=android/release.keystore
    - storePassword=${KEYSTORE_PASSWORD}
    - keyAlias=${KEY_ALIAS}
    - keyPassword=${KEY_PASSWORD}
  - Optionally decode a base64 keystore into android/release.keystore when KEYSTORE_BASE64 is provided
  - Use the signing config in Gradle to sign the release APK
- Local development guidance:
  - If a keystore is not available, explain that the release APK cannot be signed; provide steps to generate a local keystore and populate android/keystore.properties for testing

3) AndroidManifest and VPN service declarations
- Confirm HaloVpnService andHaloVpnForegroundService declarations are present in AndroidManifest.xml with correct permissions (e.g., BIND_VPN_SERVICE) and proper service attributes
- Ensure foreground service lifecycle is compatible with Play policies
- Validation steps:
  - Open AndroidManifest.xml and verify service blocks
  - Ensure no conflicting permissions or intents exist

4) Observability and logging
- Integrate ProdLogger for native Android side:
  - Added ProdLogger.java with info and error methods
  - Refactor HaloVpnService and HaloVpnForegroundService to route logs through ProdLogger
- Establish a lightweight telemetry surface (no PII) for future Crashlytics/Analytics
- Validation:
  - Build a release APK and confirm logs appear under the ProdLogger tag

5) Release tooling and documentation

  - Signing config resolves to provided keystore when present
