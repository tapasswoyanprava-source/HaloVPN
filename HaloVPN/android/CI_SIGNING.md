Android Release Signing and CI Signing Documentation

1. Purpose
This document describes how release signing is provisioned in CI for Android builds, including how keystore material is supplied securely and consumed by Gradle during the release build.

2. CI Signing flow (GitHub Actions)
- The CI workflow creates signing configuration at the path android/keystore.properties.
- It attempts to source the keystore from secrets and, if available, a base64-encoded keystore, then decodes it to the file android/release.keystore.
- Gradle is configured to read signing information from android/keystore.properties and use the actual keystore file (android/release.keystore) for release signing.

3. How secrets are consumed
- Secrets used:
  - KEYSTORE_PASSWORD: keystore password
  - KEY_ALIAS: key alias
  - KEY_PASSWORD: key password
  - (Optional) KEYSTORE_BASE64: optional base64-encoded keystore binary; if provided, it will be decoded to android/release.keystore

4. File layout and behavior
- android/keystore.properties
  - Generated by CI step:
    - storeFile=android/release.keystore
    - storePassword=${KEYSTORE_PASSWORD}
    - keyAlias=${KEY_ALIAS}
    - keyPassword=${KEY_PASSWORD}
- android/release.keystore
  - Generated by CI if KEYSTORE_BASE64 is provided. The CI step decodes KEYSTORE_BASE64 into this file and logs a message indicating the keystore was decoded.

5. Local development considerations
- For local builds, if you do not provide a release keystore, the Gradle script will log a warning and will skip signing for release. This means you cannot assembleRelease locally without providing signing configuration.
- To sign locally, place a keystore at android/release.keystore and update android/keystore.properties with the corresponding values or ensure your local Gradle signing config points to the keystore appropriately.

6. Security notes
- Do not commit real keystore files or real signing secrets into the repository.
- Use GitHub Secrets (or CI secret storage) to supply KEYSTORE_PASSWORD, KEY_ALIAS, KEY_PASSWORD, and optional KEYSTORE_BASE64.
- The CI workflow decouples signing content from repo contents by generating android/keystore.properties at runtime.

7. Change history
- This document applies to patches that add CI-based signing using a keystore file supplied via CI secrets and base64 payload, as described above.
